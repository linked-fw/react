# 005 — Hub imports: react

## PR

### Summary

A package's linked components become data. Given a package name and the exports of its
`src/components/index.ts`, `@_linked/react` returns a deterministic Turtle file describing each
component (export name, start shape, query shape, query wire format), which `linked build`
(`@_linked/cli`) writes next to `shapes.ttl` as `lib/esm/data/components.ttl`. A host that runs
apps can then load a package's components as a graph without importing its code. The generator
lives with the component factory, so the format follows the react release that writes it; the
CLI and the host never interpret component objects.

### Changes

- `src/utils/componentIndex.ts` (subpath `@_linked/react/utils/componentIndex`, covered by the
  `./*` export):
  - `componentIndexEntries(packageName, exports, warnings?)` → `ComponentIndexEntry[]`
    (`{iri, exportName, set, startShape, queryShape, query}`), one per component object, aliases
    collapsed to the code-point-smallest export name, sorted by IRI.
  - `componentIndexTurtle(packageName, exports, warnings?)` → the fixed-form Turtle, or
    `undefined` when the module exports no linked component.
  - `canonicalJson` (object keys sorted recursively, no whitespace).
  - IRIs come from core's `getPackageUri` and the `coreOntology`/`rdf` accessors, never string
    literals; a linked component is recognised by its markers, cross-copy safe

## Details

### Contract: the component index file (K8 in the hosting application's plan 282)

The generator half lives here; the build step is in `@_linked/cli`, the terms in `@_linked/core`'s
ontology.

- **Enumeration.** A package offers components through `src/components/index.ts`
  (`lib/esm/components/index.js`): its named exports. Every export that is a linked component
  (made by `linkedComponent`/`linkedSetComponent`: carries `.query` and `.shape`) is indexed;
  other exports are ignored. No `components/index`, no file. A component exported under several
  names is one entry, named by the code-point-smallest of them. A component with no export is not
  indexed; `options.name` names the live-query template only, never the index entry.
- **File.** `lib/esm/data/components.ttl`, written by the CLI build step `Writing components.ttl`
  (right after `Writing shapes.ttl`) in a child `node` that imports `lib/esm/package.js` (when
  present), `lib/esm/shapes/index.js` (when present) and `lib/esm/components/index.js`, with asset
  hooks, then calls `componentIndexTurtle(packageName, componentsModule)` from
  `@_linked/react/utils/componentIndex` of the `@_linked/react` the package resolves.
  `packageName` is the name in `linkedPackage('<name>')` (else `package.json`'s). No linked
  component, no file; a file from an earlier build is removed whenever none is written. A react
  without `utils/componentIndex`: skipped with a warning. A module that throws on import fails the
  build. `--skip-shape-check` skips this step too.
- **Vocabulary** (`https://linked.cm/ont/core/`, prefix `core:`, in `@_linked/core`'s ontology
  module and `core.ttl`): classes `core:Component`, `core:SetComponent` (`rdfs:subClassOf
  core:Component`), `core:ComponentsGraph`; properties `core:definesComponent` (package →
  component), `core:exportName` (`xsd:string`), `core:startShape` and `core:queryShape` (→ a
  `sh:NodeShape` IRI), `core:query` (an `rdf:JSON` literal).
- **IRIs.** A component: `{package IRI}/component/{encodeURIComponent(exportName)}`, where the
  package IRI is core's `getPackageUri(packageName)`. A host stores the file's triples unchanged
  in its own components graph of the package record; the component IRIs stay the package's.
- **Per component.** `<package> core:definesComponent <component>`; `<component> a
  core:Component` (and `core:SetComponent` for a `linkedSetComponent`); `core:exportName`;
  `core:startShape` = the NodeShape IRI of the component's `.shape`; `core:queryShape` = the wire
  format's `shape`; `core:query` = `QueryBuilder.toJSON()` of the component's query (a set
  component's one-key wrapper unwrapped) as canonical JSON, typed `rdf:JSON`. Start shape and
  query shape are the same IRI today (react derives `.shape` from the query); the two fields stay
  apart on purpose. A component whose query throws in `toJSON` is left out, with a warning naming
  it.
- **Queries bound at definition time** are recorded as `toJSON` writes them in the clean child,
  where no query context is set: `.for(getQueryContext('x'))` → `"subject":{"@ctx":"x"}`,
  `.for('<iri>')` → `"subject":"<iri>"`, `.for(null)` → `"nullSubject":true`.
  `QueryBuilder.fromJSON` reads all three back.
- **Determinism.** One fixed prefix block (`core`, `rdf`, `xsd`), subjects sorted (package first,
  then components by IRI), `a` first and the other predicates sorted, one statement per line, no
  blank nodes; the same build gives the same bytes, whatever the export order. The file carries no
  hash: the host hashes its bytes and replaces the whole graph when the hash changes.

Example (`my-app`, one component of each kind; JSON shortened):

```turtle
@prefix core: <https://linked.cm/ont/core/> .
@prefix rdf: <http://www.w3.org/1999/02/22-rdf-syntax-ns#> .
@prefix xsd: <http://www.w3.org/2001/XMLSchema#> .

<https://linked.cm/pkg/my-app> core:definesComponent <https://linked.cm/pkg/my-app/component/PersonList> , <https://linked.cm/pkg/my-app/component/PersonPreview> .
<https://linked.cm/pkg/my-app/component/PersonList> a core:Component , core:SetComponent ; core:exportName "PersonList" ; core:query "{\"fields\":[…],\"shape\":\"https://linked.cm/shape/schema/Person\",\"v\":1}"^^rdf:JSON ; core:queryShape <https://linked.cm/shape/schema/Person> ; core:startShape <https://linked.cm/shape/schema/Person> .
<https://linked.cm/pkg/my-app/component/PersonPreview> a core:Component ; core:exportName "PersonPreview" ; core:query "{…}"^^rdf:JSON ; core:queryShape <https://linked.cm/shape/schema/Person> ; core:startShape <https://linked.cm/shape/schema/Person> .
```

### Decisions that shaped it

- The generator is in `@_linked/react`, not the CLI: the format follows the react release that
  writes it, and the CLI only loads the built package.
- Start shape and query shape are separate fields although equal today, so a component whose
  query starts elsewhere needs no format change.
- The index uses the export name, never `options.name`; ordering depends neither on export order
  nor on `toJSON`'s key order.
- The file is deterministic and unhashed; change detection is the consumer's (hash of the bytes,
  whole-graph replace).
