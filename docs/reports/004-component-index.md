# 004 — Component index

## PR

### Summary

React generates the component index K8 defines; the CLI only loads the built package and writes
the file (cli report 042, which holds the whole step, the sandbox run and the decision ledger).

### Changes

- `src/utils/componentIndex.ts`: `componentIndexEntries(packageName, exports, warnings?)` →
  `ComponentIndexEntry[]` (`{iri, exportName, set, startShape, queryShape, query}`, sorted by IRI,
  aliases collapsed to the code-point-smallest name); `componentIndexTurtle(packageName, exports,
  warnings?)` → K8's fixed Turtle or `undefined`; `canonicalJson`. IRIs from core's
  `getPackageUri`, `coreOntology` and `rdf` accessors.
- `linkedSetComponent` sets `setComponent: true` on its result; `LinkedComponent` and
  `LinkedSetComponent` gain the optional field.
- README: "Export your components from `src/components/index.ts`".
- Peer `@_linked/core` `^2.46.0` (the terms); changeset (minor).
- Test `src/tests/component-index.test.tsx` (10 cases: single and set components, canonical JSON,
  aliases, ignored exports, `.for(getQueryContext('x'))`/`.for(iri)`/`.for(null)` with `fromJSON`
  read-back, a query that does not serialize, byte stability across export order, no component,
  a non-ASCII export name, the marker).
